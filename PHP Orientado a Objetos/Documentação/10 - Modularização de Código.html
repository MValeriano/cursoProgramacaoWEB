Modularização de Código em PHP

Usando require, include e suas variantes para organizar e reutilizar definições.

I. Inclusão de Arquivos e Tratamento de Erro

require (CRÍTICO)

Usado para arquivos essenciais (conexão DB, classes base). Se o arquivo falhar, gera Fatal Error e para a execução imediatamente.

include (OPCIONAL)

Usado para arquivos opcionais (funções utilitárias). Se o arquivo falhar, gera apenas Warning e o script continua a ser executado.

require_once / include_once

Garante que o arquivo seja incluído e avaliado apenas uma vez. Essencial para evitar a Redefinição de classes, funções e constantes.

Prática Recomendada: Omissão da Tag de Fechamento (?>)

Em arquivos que contêm somente código PHP (classes, configurações, handlers), a tag de fechamento `?>` deve ser OMITIDA.

Motivo: Evita a saída acidental de espaços ou quebras de linha após o fechamento, o que pode corromper cabeçalhos HTTP (Sessões, Cookies).

II. 5 Exercícios de Raciocínio Estrutural

1. Gerenciamento de Dependências Críticas

Usar `require` para dependências cruciais (`config.php`) e `include` para opcionais (`mensagens_uteis.php`).

// index.php
<?php
// 1. Conexão crítica (require -> Fatal Error se falhar)
require 'config.php';

// 2. Função opcional (include -> Warning, mas o script continua)
include 'mensagens_uteis.php';

echo "Sistema carregado (Constantes do DB em config.php são essenciais).";
// ... O código pode continuar a rodar mesmo sem mensagens_uteis.php ...
?>

2. O Desafio da Reutilização Segura (Evitando Redefinição)

Impedir a redeclaração de funções ou classes usando o sufixo _once.

// funcoes.php
<?php
function calcula_imc($p, $a) { return $p / ($a * $a); }

// relatorio.php
require_once 'funcoes.php'; // Inclui 1/2
require_once 'funcoes.php'; // Ignorado, prevenindo Fatal Error de redefinição

echo "IMC calculado: " . calcula_imc(75, 1.75);
?>

3. Padrões de Design em OO (classes)

Em POO, use sempre `_once` para carregar classes e evitar redefinições acidentais.

// classes/Pessoa.class.php (sem tag de fechamento)
<?php class Pessoa { //... }

// objetos.php
require_once 'classes/Pessoa.class.php'; // Necessário para instanciar objetos
require_once 'classes/Conta.class.php';

$carlos = new Pessoa();
echo "Classes carregadas com sucesso.";
?>

4. Sintaxe Pura e Omissão do Fechamento

Omitindo a tag de fechamento (`?>`) em arquivos puramente PHP para evitar problemas de `Headers Already Sent`.

// dbh.inc.php (ARQUIVO PURO PHP)
<?php
function conectar_db() {
// Lógica de conexão com o banco de dados aqui...
return true;
}
// NENHUMA TAG DE FECHAMENTO (?>) DEVE SER USADA AQUI.

// index.php
require 'dbh.inc.php';
echo "Arquivo de conexão carregado com segurança.";
?>

5. Controle de Fluxo Condicional com Inclusão

Usando `if/else` e `file_exists` para carregar o arquivo correto e finalizar o script com uma mensagem personalizada se a dependência falhar.

// index.php
<?php
$config_carregado = false;

if (file_exists('config_dev.php')) {
require 'config_dev.php'; // Tenta o ambiente de Desenvolvimento
$config_carregado = true;
} elseif (file_exists('config_prod.php')) {
require 'config_prod.php'; // Se falhar, tenta o de Produção
$config_carregado = true;
}

if (!$config_carregado) {
die("ERRO FATAL: Arquivo de configuração não encontrado.");
}

echo "Configuração carregada. Continuação do script...";
?>
