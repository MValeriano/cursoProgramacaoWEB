Operadores Lógicos em PHP: Teoria e Prática

6 Desafios práticos para dominar a lógica condicional.

Resumo

Os Operadores Lógicos são ferramentas essenciais em PHP, utilizadas para combinar expressões lógicas entre si, agrupando testes condicionais. Eles retornam um valor booleano (`TRUE` ou `FALSE`) e são cruciais para a construção de estruturas de controle de fluxo, como os comandos `IF`.

O PHP oferece vários operadores lógicos, sendo os principais: `AND` (`&&`), `OR` (`||`), `XOR` (`xor`), e `NOT` (`!`). O uso correto desses operadores permite evitar o aninhamento excessivo de condições (*nesting*), o que resulta em código mais limpo e legível.

Abaixo estão 6 exercícios estruturados com problemas práticos que exigem o uso dos operadores lógicos para a sua resolução.

6 Exercícios sobre Operadores Lógicos em PHP

Exercício 1: Validação de Múltiplos Critérios Obrigatórios (`AND` / `&&`)

Problema: Você está implementando o *backend* de um sistema de pedidos online. Para que um pedido seja processado, ele deve atender a todas as seguintes condições: o valor total deve ser maior que R$ 50,00 E o estoque do produto principal (`$estoque_disponivel`) deve ser superior a 0.

Conceitos Chave: Operador Lógico `AND` (`&&`), Operadores Relacionais (`>`, `> 0`), Estrutura `IF`.

Enunciado do Exercício:

  1. Crie as variáveis: $valor_pedido = 65.00; e $estoque_disponivel = 5;.
  2. Use uma estrutura `IF` para checar se ambas as condições são verdadeiras: $valor_pedido é maior que 50 E $estoque_disponivel é maior que 0.
  3. Se a expressão composta retornar `TRUE`, imprima: "Pedido Aprovado e Enviado para o Depósito.".
  4. Se a expressão retornar `FALSE`, imprima: "Pedido Retido: Critérios insuficientes."
  5. Desafio de Raciocínio: Modifique $estoque_disponivel para `0`. Explique por que, embora $valor_pedido ainda satisfaça sua condição, o resultado final do `IF` foi `FALSE`.

<?php
// --- Cenário 1 ---
echo "--- Cenário 1 ---\n";
// 1. Variáveis
$valor_pedido = 65.00;
$estoque_disponivel = 5;

// 2. Estrutura IF com AND
if ($valor_pedido > 50 && $estoque_disponivel > 0) {
    // 3. Resultado TRUE
    echo "Pedido Aprovado e Enviado para o Depósito.\n";
} else {
    // 4. Resultado FALSE
    echo "Pedido Retido: Critérios insuficientes.\n";
}

// --- Cenário 2 (Desafio) ---
echo "\n--- Desafio de Raciocínio ---\n";
// 5. Modificando a variável
$estoque_disponivel = 0;
echo "Estoque modificado para: $estoque_disponivel\n";

if ($valor_pedido > 50 && $estoque_disponivel > 0) {
    echo "Pedido Aprovado e Enviado para o Depósito.\n";
} else {
    echo "Pedido Retido: Critérios insuficientes.\n";
}

echo "\nExplicação: O resultado é FALSE porque o operador 'AND' (&&) exige que TODAS as condições sejam verdadeiras. Embora a condição do valor (65 > 50) seja TRUE, a condição do estoque (0 > 0) é FALSE. Como uma das partes é falsa, a expressão inteira se torna falsa.\n";
?>

Exercício 2: Verificação de Erro em Formulário (`OR` / `||`)

Problema: Você precisa validar a submissão de um formulário de login. Um erro de validação deve ser disparado se o campo $email estiver vazio OU se o campo $senha estiver vazio. Se houver falha em pelo menos um desses campos obrigatórios, o sistema deve impedir o login.

Conceitos Chave: Operador Lógico `OR` (`||`), Função `empty()`.

Enunciado do Exercício:

  1. Crie as variáveis $email = "usuario@exemplo.com"; e $senha = ""; (vazia).
  2. Utilize o operador lógico `OR` (`||`) dentro de um `IF` para verificar se $email está vazio OU se $senha está vazio.
  3. Se a condição `OR` retornar `TRUE`, defina uma variável $erro_login = TRUE; e imprima "Login negado. Preencha todos os campos.".
  4. Se retornar `FALSE`, imprima "Tentativa de login processada.".
  5. Foco Estrutural: Altere o valor de $email para uma *string* vazia e o de $senha para um valor. O resultado muda? Por que, neste cenário de validação, é impossível usar o operador `AND`?

<?php
// --- Cenário 1 ---
echo "--- Cenário 1 ---\n";
// 1. Variáveis
$email = "usuario@exemplo.com";
$senha = "";
$erro_login = FALSE;

// 2. Verificação com OR
if (empty($email) || empty($senha)) {
    // 3. Resultado TRUE
    $erro_login = TRUE;
    echo "Login negado. Preencha todos os campos.\n";
} else {
    // 4. Resultado FALSE
    echo "Tentativa de login processada.\n";
}

// --- Cenário 2 (Foco Estrutural) ---
echo "\n--- Foco Estrutural ---\n";
// 5. Alterando as variáveis
$email = "";
$senha = "123456";
echo "Email: (vazio), Senha: (preenchida)\n";

if (empty($email) || empty($senha)) {
    echo "Login negado. Preencha todos os campos.\n";
} else {
    echo "Tentativa de login processada.\n";
}

echo "\nExplicação: O resultado não muda porque o operador 'OR' (||) precisa que APENAS UMA das condições seja verdadeira. No primeiro caso, a senha estava vazia. No segundo, o email estava vazio. Em ambos, uma das condições foi atendida.\n";
echo "Seria impossível usar 'AND' aqui porque ele exigiria que AMBOS os campos estivessem vazios para dar o erro, o que não é a lógica desejada.\n";
?>

Exercício 3: Controle de Acesso Exclusivo (`XOR` / `xor`)

Problema: Em um sistema de emissão de licenças, um usuário só pode emitir um novo documento se ele for um Administrador OU um Editor, mas NUNCA se ele for ambos. O acesso deve ser concedido se *apenas um* dos status for verdadeiro.

Conceitos Chave: Operador Lógico `XOR` (`xor`), Condição Exclusiva.

Enunciado do Exercício:

  1. Crie as variáveis booleanas $is_admin = TRUE; e $is_editor = TRUE;.
  2. Utilize o operador lógico `XOR` (Ou Exclusivo) para verificar se $is_admin ou $is_editor é verdadeiro, de forma exclusiva.
  3. Se o `XOR` retornar `TRUE`, imprima "Acesso liberado para emissão."
  4. Se retornar `FALSE`, imprima "Acesso restrito. Condição exclusiva não atendida."
  5. Desafio de Raciocínio: Explique como o resultado muda se você alterar $is_editor para `FALSE`. O que o `XOR` garante que o `OR` simples não garante?

<?php
// --- Cenário 1 ---
echo "--- Cenário 1 (Admin: TRUE, Editor: TRUE) ---\n";
// 1. Variáveis
$is_admin = TRUE;
$is_editor = TRUE;

// 2. Verificação com XOR
if ($is_admin xor $is_editor) {
    // 3. Resultado TRUE
    echo "Acesso liberado para emissão.\n";
} else {
    // 4. Resultado FALSE
    echo "Acesso restrito. Condição exclusiva não atendida.\n";
}

// --- Cenário 2 (Desafio) ---
echo "\n--- Desafio de Raciocínio (Admin: TRUE, Editor: FALSE) ---\n";
// 5. Alterando a variável
$is_editor = FALSE;

if ($is_admin xor $is_editor) {
    echo "Acesso liberado para emissão.\n";
} else {
    echo "Acesso restrito. Condição exclusiva não atendida.\n";
}

echo "\nExplicação: O resultado muda para 'Acesso liberado' porque agora apenas UMA das condições é TRUE.\n";
echo "O 'XOR' garante que a expressão só seja verdadeira se um e apenas um dos lados for verdadeiro. O 'OR' simples retornaria TRUE nos dois cenários (TRUE/TRUE e TRUE/FALSE), pois ele não se importa se ambos são verdadeiros.\n";
?>

Exercício 4: Negação Lógica e Inversão de Sentido (`NOT` / `!`)

Problema: Você tem uma variável booleana que rastreia se um erro $tem_erro ocorreu. Seu código de cálculo (`$pode_calcular`) só deve ser executado se não houver nenhum erro. Você precisa usar o operador de negação para inverter o valor booleano e controlar o fluxo do programa.

Conceitos Chave: Operador Lógico `NOT` (`!`), Inversão Booleana, Estrutura `IF`.

Enunciado do Exercício:

  1. Crie a variável $tem_erro = FALSE;.
  2. Use o operador de negação `!` na frente de $tem_erro dentro de um `IF` para verificar a condição "SE NÃO HOUVER ERRO".
  3. Se a condição for verdadeira, imprima "Cálculo Iniciado: Erro Inexistente.".
  4. Se a condição for falsa (o que significa que houve erro), imprima "Cálculo Interrompido: Erro Detectado.".
  5. Desafio de Raciocínio: Altere $tem_erro para `TRUE`. O que o operador `!` faz com o valor booleano da variável antes de o `IF` testar a condição?

<?php
// --- Cenário 1 ---
echo "--- Cenário 1 (tem_erro = FALSE) ---\n";
// 1. Variável
$tem_erro = FALSE;

// 2. Verificação com NOT (!)
if (!$tem_erro) { // Se NÃO tem_erro (ou seja, se TRUE)
    // 3. Resultado TRUE
    echo "Cálculo Iniciado: Erro Inexistente.\n";
} else {
    // 4. Resultado FALSE
    echo "Cálculo Interrompido: Erro Detectado.\n";
}

// --- Cenário 2 (Desafio) ---
echo "\n--- Desafio de Raciocínio (tem_erro = TRUE) ---\n";
// 5. Alterando a variável
$tem_erro = TRUE;

if (!$tem_erro) {
    echo "Cálculo Iniciado: Erro Inexistente.\n";
} else {
    echo "Cálculo Interrompido: Erro Detectado.\n";
}

echo "\nExplicação: O operador '!' inverte o valor booleano da variável. Quando \$tem_erro é TRUE, a expressão '!\$tem_erro' se torna FALSE antes de ser avaliada pelo IF. Por isso, o bloco 'else' é executado.\n";
?>

Exercício 5: Múltiplas Condições Aninhadas (Uso Misto de `AND` e `OR`)

Problema: Para liberar um pagamento, o cliente deve ser (1) VIP E ter pago o frete OU (2) Ter o status "Pronto para Envio". Você precisa construir uma expressão lógica complexa que combine `AND` e `OR` (e parênteses para precedência) para determinar se o pagamento é liberado.

Conceitos Chave: Precedência de Operadores (Parênteses), Combinação de `AND` e `OR`.

Enunciado do Exercício:

  1. Crie as variáveis: $cliente_vip = FALSE;, $frete_pago = TRUE;, e $status_pronto = TRUE;.
  2. Construa a expressão lógica completa no seu `IF` (utilizando parênteses para garantir que a condição VIP + Frete seja avaliada primeiro).
    Lógica: (Cliente VIP AND Frete Pago) OR (Status Pronto)
  3. Se a expressão for `TRUE`, imprima "Pagamento Liberado.".
  4. Se a expressão for `FALSE`, imprima "Pagamento Pendente.".
  5. Foco Estrutural: Explique como os parênteses controlam a precedência e garanta que o resultado seja "Pagamento Liberado." neste caso, devido à variável $status_pronto.

<?php
// 1. Variáveis
$cliente_vip = FALSE;
$frete_pago = TRUE;
$status_pronto = TRUE;

// 2. Expressão Lógica com parênteses
// ($cliente_vip && $frete_pago) -> (FALSE && TRUE) -> FALSE
// (FALSE) || $status_pronto -> (FALSE || TRUE) -> TRUE
if (($cliente_vip && $frete_pago) || $status_pronto) {
    // 3. Resultado TRUE
    echo "Pagamento Liberado.\n";
} else {
    // 4. Resultado FALSE
    echo "Pagamento Pendente.\n";
}

// 5. Explicação
echo "\nExplicação Estrutural: Os parênteses forçam a avaliação da expressão 'AND' primeiro. O resultado de (\$cliente_vip && \$frete_pago) é FALSE.\n";
echo "A expressão se torna: 'FALSE || \$status_pronto'. Como \$status_pronto é TRUE e o operador 'OR' só precisa de um lado verdadeiro, a condição geral se torna TRUE, liberando o pagamento.\n";
?>

Exercício 6: Precedência e Tipos de Dados (Valores Falsos)

Problema: O PHP considera certos valores (como `0` e *string* vazia) como `FALSE` em comparações lógicas. Você precisa testar como o operador `OR` lida com o valor numérico zero quando combinado com uma variável `TRUE`.

Conceitos Chave: Precedência, Tipos de Dados Falsos (`0`), Operador Lógico `OR`.

Enunciado do Exercício:

  1. Crie as variáveis: $numero_de_erros = 0; (inteiro) e $usuario_logado = TRUE; (booleano).
  2. Crie a expressão: if ($numero_de_erros OR $usuario_logado).
  3. Imprima a mensagem: "Sistema está operacional.".
  4. Raciocínio Estrutural: O que o PHP considerou como o valor booleano de $numero_de_erros? Mesmo sendo `FALSE`, por que o bloco de comandos foi executado? O que o `OR` requer para retornar `TRUE`?

<?php
// 1. Variáveis
$numero_de_erros = 0;
$usuario_logado = TRUE;

// 2. Expressão Lógica
if ($numero_de_erros || $usuario_logado) {
    // 3. Impressão
    echo "Sistema está operacional.\n";
} else {
    echo "Sistema com falha ou usuário deslogado.\n";
}

// 4. Raciocínio Estrutural
echo "\n--- Raciocínio Estrutural ---\n";
echo "O PHP converteu o valor 0 (inteiro) para o booleano FALSE durante a avaliação da condição.\n";
echo "O bloco de comandos foi executado porque a expressão se tornou (FALSE || TRUE). O operador 'OR' só precisa que um dos lados seja TRUE para que toda a expressão retorne TRUE. Como \$usuario_logado era TRUE, a condição foi satisfeita.\n";
?>
