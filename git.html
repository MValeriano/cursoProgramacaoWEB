Aula de Git Básico — Passo a Passo Didático

1) O que é Git? e o que é um repositório?

  • O **Git** é uma ferramenta que registra as mudanças feitas em arquivos ao longo do tempo. Pense nela como um histórico automático de tudo que foi alterado em um projeto.
  • **Repositório (repo)** é o local onde esse histórico e os arquivos ficam guardados.
    • **Repositório local:** está no seu computador (uma pasta onde o Git guarda arquivos escondidos).
    • **Repositório remoto (on-line):** é uma cópia do repositório guardada na internet (ex.: GitHub, GitLab, Bitbucket). Permite compartilhar e sincronizar com outras pessoas.

Repositórios mais usados

  • **GitHub** — muito popular, fácil de usar, usado por pessoas e empresas.
  • **GitLab** — parecido com GitHub; tem versões on-line e versões que empresas instalam internamente.
  • **Bitbucket** — também popular; integrado com outras ferramentas (ex.: Jira).
Usar GitHub é suficiente: é grátis para projetos públicos e tem interface amigável.

2) Conceitos-chave

  • **Commit:** como “tirar uma foto” do estado atual dos arquivos. Cada commit tem uma mensagem que explica a mudança.
  • **Stage / Staging area:** é como uma bandeja onde você coloca os arquivos que quer incluir na próxima foto (commit).
  • **Branch (ramo):** uma estrada paralela. Permite trabalhar em algo novo (ex.: uma nova funcionalidade) sem mexer na estrada principal.
  • **Merge:** juntar o trabalho da branch de volta para a branch principal.
  • **Remote:** o repositório on-line (por exemplo, `origin` é o nome comum dado ao repositório remoto principal).
  • **Clone:** criar uma cópia local de um repositório remoto.
  • **Pull:** pegar alterações do remoto e aplicar na sua cópia local.
  • **Push:** enviar suas alterações locais para o remoto.

3) Principais comandos

  • `git init` — cria um repositório Git novo na pasta atual.
  • `git clone ` — copia um repositório remoto para o seu computador.
  • `git status` — mostra o estado atual (o que foi modificado, o que está na stage, etc.).
  • `git add ` — coloca o arquivo na stage (prepara para commit). `git add .` adiciona tudo.
  • `git commit -m "Mensagem"` — cria um commit com as mudanças staged.
  • `git push origin main` — envia commits para o repositório remoto (substitua `main` pela branch).
  • `git pull` — puxa (baixa) mudanças do remoto e aplica aqui.
  • `git branch` — lista branches locais. `git branch nome-da-branch` cria uma nova.
  • `git checkout nome-da-branch` — muda para a branch especificada. (Hoje se usa `git switch` também.)
  • `git merge nome-da-branch` — junta a branch indicada na branch atual.
  • `git log` — mostra o histórico de commits.
  • `git remote add origin ` — associa um repositório remoto à sua pasta local com o nome `origin`.
  • `.gitignore` — arquivo onde você lista arquivos/pastas que o Git deve ignorar.

4) Passo-a-passo prático: criar projeto local e enviar para um repositório on-line

- Windows (com *Git Bash*), Mac ou Linux — os comandos são os mesmos.

A) Preparar o ambiente

  1. Instalar Git: ir ao site do Git e instalar.

    - Após instalar, abrir o Terminal.

  2. Configurar seu nome e e-mail (apenas da primeira vez):

    Em casa digitar :

    git config --global user.name "Seu Nome"
git config --global user.email "seu.email@exemplo.com"

    Porque isso grava o nome e o e-mail para todos os usuários que usarem aquela máquina depois.

    Aqui digitaremos :

    git config user.name "Seu Nome"
git config user.email "seu.email@exemplo.com"

    Assim ninguém que acesse o git depois nesta máquina verá seus dados.

    Explicação:

    • o Git registra quem fez cada commit.
    • Esses comandos dizem ao Git: “Quando você fizer commits nesta pasta, use este nome e este e-mail.”
    • Nada será salvo como configuração global da máquina.
    • Se outro aluno abrir outro projeto diferente, precisará configurar novamente — o que é bom, pois evita misturar identidades.

    Como verificar a configuração local:

    git config --list

    Ou somente as informações de usuário:

    git config user.name
git config user.email

    Como apagar a configuração local (se precisar):

    git config --unset user.name
git config --unset user.email

B) Criar um projeto local e inicializar o Git

1. Criar uma pasta para o projeto e entrar nela:

mkdir meu-projeto
cd meu-projeto

2. Inicializar o Git (cria a pasta oculta `.git`):

git init

Resultado esperado: Git informa que um repositório foi criado. Agora sua pasta é um repositório local.

3. Criar um arquivo simples (por exemplo `README.md`) e escrever algo:

echo "# Meu Projeto" > README.md

4. Verificar o estado:

git status

Explicação: mostrará que `README.md` é um arquivo novo não rastreado.

5. Adicionar o arquivo à stage:

git add README.md

ou adicionar tudo:

git add .

6. Fazer o primeiro commit:

git commit -m "Primeiro commit: adiciona README"

Explicação: agora há uma “foto” do projeto.

C) Criar o repositório remoto (no GitHub/GitLab/Bitbucket)

(Explique em sala mostrando a interface do site; passos gerais:)

  1. Entrar no site github.com e fazer login.
  2. Clicar em “New repository” / “Criar repositório”.
  3. Dar um nome (ex.: `landing_page`) e clicar em criar — normalmente escolher sem criar README (já temos um local).
  4. O site vai mostrar instruções com uma URL (algo como `https://github.com/usuario/landing_page.git`).

Observação: se o repositório está privado, talvez precise autenticação (senha, token). Hoje é comum usar token em vez de senha para enviar (push).

D) Conectar o repositório local ao remoto e enviar (push)

1. Associar o remoto com nome `origin` (substitua a URL):

git remote add origin https://github.com/usuario/landing_page.git

2. Enviar sua branch principal (ex.: `main`) para o remoto:

Se sua branch local se chama `master`, mude o nome ou use `master`. Hoje o padrão costuma ser `main`. Para renomear:

git branch -M main

Agora enviar:

git push -u origin main

Explicação: `-u` configura `origin/main` como destino padrão para futuros `git push`. Depois disso, no site você verá os arquivos.

5) Clonar um repositório (pegar do remoto para o seu computador)

Se alguém já tem o projeto no GitHub e você quer uma cópia:

git clone https://github.com/usuario/landing_page.git

Isso cria a pasta `landing_page` com todo o histórico. Depois:

cd meu-projeto

6) Fluxo de trabalho diário (simples e seguro)

  1. `git pull` — atualizar sua cópia local com as mudanças do remoto.
  2. Fazer alterações nos arquivos (editar).
  3. `git status` — ver o que mudou.
  4. `git add ` ou `git add .` ou `git add *` — preparar as mudanças.
  5. `git commit -m "mensagem explicando as mudanças"` — salvar localmente.
  6. `git push` — enviar para o remoto.

sempre puxe (pull) antes de começar (para evitar conflitos), commit localmente, e envie quando terminar.

7) Branches (o que são e como usar)

O que é uma branch?

  • É uma linha separada de trabalho. A branch principal costuma se chamar `main` (ou `master`).
  • Imagine: a branch `main` é a versão pública; você cria uma branch `nova-funcionalidade` para trabalhar sem estragar o que está em `main`.

Como criar, usar e juntar uma branch

1. Criar uma branch:

git branch nova-funcionalidade

2. Mudar para a branch (começar a trabalhar nela):

git checkout nova-funcionalidade (ou `git switch nova-funcionalidade` — comando mais novo e direto)

3. Fazer mudanças, `git add`, `git commit` normalmente.

4. Voltar para `main`:

git checkout main

5. Juntar (merge) a branch na `main`:

git merge nova-funcionalidade

6. Enviar (`push`) a branch ou `main` para o remoto:

  • Para enviar a nova branch para o remoto: 
    git push -u origin nova-funcionalidade
  • Para enviar a `main` depois do merge: 
    git push origin main

Delete branch local quando não for mais necessária:

git branch -d nova-funcionalidade

8) Conflitos (quando duas pessoas mudam a mesma linha)

  • Acontece ao fazer `git merge` ou `git pull` quando existe alteração conflitante.
  • O Git marca o arquivo com sinais `<<<<<<<`, `=======`, `>>>>>>>`.

Resolução simples:

  1. Abra o arquivo, leia as duas versões e escolha o que manter (ou junte manualmente).
  2. Salve o arquivo.
  3. `git add ` e `git commit` (o commit conclui a resolução do conflito).

9) Arquivo `.gitignore`

Coloque nomes de arquivos/pastas que não devem entrar no repositório (ex.: arquivos de configuração pessoal, pastas `node_modules`, arquivos de build).

Exemplo simples de .gitignore:

# arquivos temporários do sistema
.DS_Store
Thumbs.db

# node
node_modules/

# logs
*.log

# IDEs
.vscode/
.idea/

Crie esse arquivo na raiz do seu projeto antes de commitar as coisas que não quer subir.

10) Comandos úteis de recuperação / inspeção

  • `git log --oneline` — ver histórico resumido.
  • `git diff` — ver diferenças não staged.
  • `git checkout -- arquivo` — desfazer mudanças em um arquivo (irá substituí-lo pela versão do último commit).
  • `git reset HEAD arquivo` — tirar um arquivo da stage antes do commit (não apaga as mudanças locais).
  • `git restore --staged arquivo` — alternativa moderna para tirar da stage.

Atenção: alguns comandos podem perder trabalho se usados sem cuidado. Sempre explique em aula e demonstre com exemplos.

11) Exercício prático

Objetivo: cada aluno cria um repositório local, envia para o GitHub, cria uma branch, faz mudanças e faz merge.

  1. Criar pasta `exercicio-git` e `git init`.
  2. Criar `README.md` e adicionar um parágrafo com nome e data.
  3. `git add .` → `git commit -m "Cria README"`.
  4. Criar repositório no GitHub (nome `exercicio-git`) e conectar remoto (`git remote add origin ...`).
  5. `git push -u origin main`.
  6. Criar branch `minha-alteracao`: `git checkout -b minha-alteracao`.
  7. Editar o `README.md` (adicionar linha “Este é meu primeiro exercício de Git”).
  8. `git add README.md` → `git commit -m "Adiciona frase de exercício"`.
  9. `git push -u origin minha-alteracao`.
  10. No GitHub, abrir um *Pull Request* (ou fazer merge local: voltar `git checkout main` e `git merge minha-alteracao` e `git push`).
  11. Apagar a branch local e remota quando concluído (opcional).

Aqui está a sequência completa de comandos para este exercício (substitua URL e branch se necessário):

mkdir exercicio-git
cd exercicio-git
git init
echo "Meu Nome e Data: 2024-01-01" > README.md
git add .
git commit -m "Cria README"
git remote add origin <URL DO SEU REPO NO GITHUB>
git push -u origin main
git checkout -b minha-alteracao
echo "Este é meu primeiro exercício de Git" >> README.md
git add README.md
git commit -m "Adiciona frase de exercício"
git push -u origin minha-alteracao

# PARA FAZER O MERGE LOCALMENTE (Passo 10)
git checkout main
git merge minha-alteracao
git push origin main

# PARA DELETAR (Passo 11)
git branch -d minha-alteracao
# Opcional: git push origin --delete minha-alteracao

12) Erros comuns e como resolver

  • **Erro: permission denied (publickey)**
    • Significa problema de autenticação SSH. Solução simples: usar HTTPS com token, ou configurar chave SSH no GitHub.
  • **Erro: failed to push some refs**
    • Normalmente porque remoto tem commits novos. Solução: `git pull --rebase` ou `git pull` e resolver conflitos, depois `git push`.
  • **Merge conflicts** — explicar como editar o arquivo e commitar.
  • **Arquivos que aparecem no git status mas deveriam ser ignorados** — ver `.gitignore`; se já foram adicionados antes, remover com `git rm --cached arquivo`.

13) Pequeno glossário final

  • **Commit:** salvar um ponto no tempo do seu projeto.
  • **Push:** enviar seus commits para a internet (repositório remoto).
  • **Pull:** trazer as mudanças do remoto para você.
  • **Clone:** copiar um repositório da internet para o computador.
  • **Branch:** “linha paralela” de trabalho.
  • **Merge:** juntar duas linhas de trabalho.
  • **Stage (add):** preparar arquivos para o commit.
  • **Remote (origin):** repositório on-line associado.

14) Folha de referência rápida (cheat-sheet)

# inicializar repo local
git init

# clonar repo remoto
git clone <url>

# ver status
git status

# adicionar / preparar
git add arquivo.txt
git add .

# gravar commit
git commit -m "mensagem clara e curta"

# ver histórico
git log --oneline

# enviar para remoto
git push origin main

# trazer do remoto
git pull

# criar e mudar para branch
git checkout -b minha-branch
# mudar para branch existente
git checkout main

# unir branch na branch atual
git merge minha-branch

# ver branches
git branch

# remover branch local
git branch -d minha-branch
