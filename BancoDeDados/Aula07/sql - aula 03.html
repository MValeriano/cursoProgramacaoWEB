AULA 3: DEFINIÇÃO DE ESTRUTURAS (DDL)

Aprenda a criar e modificar a estrutura de um banco de dados.

O que é DDL?

A **DDL** (Data Definition Language) é o conjunto de comandos SQL usado para **definir, modificar e remover a estrutura** do seu banco de dados. Com ela, você constrói a "casa" que vai guardar seus dados.

Comando CREATE: Criando Tabelas

O comando CREATE TABLE é usado para criar novas tabelas no banco de dados, definindo suas colunas, tipos de dados e restrições.

Sintaxe

CREATE TABLE [IF NOT EXISTS] nome_tabela (
    coluna1 tipo_dado [constraints],
    coluna2 tipo_dado [constraints],
    ...
    [constraints de tabela]
) [TABLESPACE tablespace_name];
);

Parâmetros Opcionais:

  • IF NOT EXISTS: Evita erro se a tabela já existir.
  • TABLESPACE: Evita erro se a tabela já existir.

Tipos de Dados mais usados

  • INTEGER: Números inteiros. Ex: idade, quantidade.
  • TEXT / VARCHAR: Cadeias de caracteres. Ex: nomes, endereços.
  • DECIMAL / REAL: Números com casas decimais. Ex: preços, saldos.
  • DATE: Armazena datas.

Constraints (Restrições)

Regras que garantem a integridade e a validade dos dados.

  • PRIMARY KEY: Identificador único para cada registro. Não pode ser nula e deve ser única. 
    -- Forma 1: Na coluna
CREATE TABLE usuarios (
	id SERIAL PRIMARY KEY,
	nome VARCHAR(100)
);

-- Forma 2: Como constraint de tabela
CREATE TABLE usuarios (
	id SERIAL,
	nome VARCHAR(100),
	PRIMARY KEY (id)
);

-- Forma 3: Chave composta
CREATE TABLE pedidos_itens (
	pedido_id INTEGER,
	item_id INTEGER,
	quantidade INTEGER,
	PRIMARY KEY (pedido_id, item_id)
);
  • FOREIGN KEY: Liga uma coluna a outra tabela, criando relacionamentos. 
    CREATE TABLE pedidos (
		id SERIAL PRIMARY KEY,
		usuario_id INTEGER,
		data_pedido DATE,
		FOREIGN KEY (usuario_id) REFERENCES usuarios(id)
	);

	-- Com ações em cascata
	CREATE TABLE pedidos (
		id SERIAL PRIMARY KEY,
		usuario_id INTEGER,
		data_pedido DATE,
		FOREIGN KEY (usuario_id) 
			REFERENCES usuarios(id)
			ON DELETE CASCADE
			ON UPDATE SET NULL
	);
  • NOT NULL: Garante que a coluna não pode ter um valor nulo. 
    CREATE TABLE produtos (
		id SERIAL PRIMARY KEY,
		nome VARCHAR(100) NOT NULL,
		descricao TEXT,
		preco DECIMAL(10,2) NOT NULL
	);
  • UNIQUE: Todos os valores na coluna devem ser únicos. 
    CREATE TABLE usuarios (
		id SERIAL PRIMARY KEY,
		email VARCHAR(255) UNIQUE,
		cpf VARCHAR(11) UNIQUE NOT NULL
	);

	-- Múltiplas colunas
	CREATE TABLE funcionarios (
		id SERIAL PRIMARY KEY,
		departamento_id INTEGER,
		matricula VARCHAR(10),
		UNIQUE (departamento_id, matricula)
	);
  • CHECK: Define uma condição que deve ser satisfeita. 
    CREATE TABLE produtos (
		id SERIAL PRIMARY KEY,
		nome VARCHAR(100) NOT NULL,
		preco DECIMAL(10,2) CHECK (preco > 0),
		estoque INTEGER CHECK (estoque >= 0)
	);

	-- Check complexo
	CREATE TABLE funcionarios (
		id SERIAL PRIMARY KEY,
		nome VARCHAR(100) NOT NULL,
		salario DECIMAL(10,2),
		data_admissao DATE,
		email VARCHAR(50) NOT NULL, 
		CHECK (salario > 0 AND data_admissao <= CURRENT_DATE),
		CHECK (email ~* '^[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Z]{2,}$')
	);
  • DEFAULT: Define um valor padrão caso nenhum valor seja fornecido. 
    CREATE TABLE pedidos (
		id SERIAL PRIMARY KEY,
		data_criacao TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
		status VARCHAR(20) DEFAULT 'pendente',
		total DECIMAL(10,2) DEFAULT 0.00
	);

Comando ALTER: Modificando Tabelas

Use o comando ALTER TABLE para adicionar, modificar ou remover colunas de uma tabela existente. É uma operação essencial para evolução do esquema do banco de dados.

Quando usar ALTER TABLE?

  • Adicionar, modificar ou remover colunas.
  • Adicionar ou remover constraints.
  • Renomear tabelas ou colunas.
  • Renomear tabelas ou colunas.
  • Modificar propriedades da tabela.

Sintaxe Geral

ALTER TABLE [IF EXISTS] nome_tabela
	ação_da_alteracao;

Principais Ações:

  • ADD COLUMN - Adicionar nova coluna.
  • DROP COLUMN - Remover coluna.
  • ALTER COLUMN - Modificar coluna.
  • RENAME TO - Renomear tabela.
  • ADD CONSTRAINT - Adicionar constraint.
  • DROP CONSTRAINT - Remover constraint.

Adicionar Coluna

-- Sintaxe básica
	ALTER TABLE nome_tabela 
	ADD COLUMN nome_coluna tipo_dado [constraints];

	-- Exemplos práticos
	ALTER TABLE usuarios 
	ADD COLUMN telefone VARCHAR(15);

	ALTER TABLE produtos 
	ADD COLUMN data_criacao TIMESTAMP DEFAULT CURRENT_TIMESTAMP;

	ALTER TABLE pedidos 
	ADD COLUMN total DECIMAL(10,2) NOT NULL DEFAULT 0.00;

Modificar Coluna

-- Sintaxe básica
	ALTER TABLE nome_tabela 
	DROP COLUMN [IF EXISTS] nome_coluna [CASCADE | RESTRICT];

	-- Exemplos
	ALTER TABLE usuarios 
	DROP COLUMN telefone;

	ALTER TABLE produtos 
	DROP COLUMN IF EXISTS observacao; -- Não causa erro se não existir

	ALTER TABLE vendas 
	DROP COLUMN comissao CASCADE; -- Remove dependências

Remover Coluna

ALTER TABLE nome_tabela 
	RENAME COLUMN nome_atual TO novo_nome;

	-- Exemplos
	ALTER TABLE clientes 
	RENAME COLUMN nome TO nome_completo;

	ALTER TABLE produtos 
	RENAME COLUMN preco TO preco_venda;

Alterar Tipo de Dado

ALTER TABLE nome_tabela 
ALTER COLUMN nome_coluna TYPE novo_tipo [USING expressao];

-- Exemplos simples
ALTER TABLE usuarios 
ALTER COLUMN idade TYPE SMALLINT;

-- Com conversão usando USING
ALTER TABLE produtos 
ALTER COLUMN preco TYPE DECIMAL(10,2) 
USING preco::decimal(10,2);

-- Conversão de texto para numérico
ALTER TABLE vendas 
ALTER COLUMN valor TYPE NUMERIC(10,2) 
USING REPLACE(valor, 'R$', '')::numeric(10,2);

Modificar Constraints de Coluna

-- Adicionar NOT NULL
ALTER TABLE nome_tabela 
ALTER COLUMN nome_coluna SET NOT NULL;

-- Remover NOT NULL
ALTER TABLE nome_tabela 
ALTER COLUMN nome_coluna DROP NOT NULL;

-- Setar valor padrão
ALTER TABLE nome_tabela 
ALTER COLUMN nome_coluna SET DEFAULT valor;

-- Remover valor padrão
ALTER TABLE nome_tabela 
ALTER COLUMN nome_coluna DROP DEFAULT;

-- Exemplos
ALTER TABLE usuarios 
ALTER COLUMN email SET NOT NULL;

ALTER TABLE produtos 
ALTER COLUMN estoque SET DEFAULT 0;

ALTER TABLE pedidos 
ALTER COLUMN status DROP DEFAULT;

Renomear Coluna

ALTER TABLE nome_tabela 
RENAME COLUMN nome_atual TO novo_nome;

-- Exemplos
ALTER TABLE clientes 
RENAME COLUMN nome TO nome_completo;

ALTER TABLE produtos 
RENAME COLUMN preco TO preco_venda;

Modificando Constraints da tabela

Adicionar Constraints

-- Primary Key
ALTER TABLE nome_tabela 
ADD PRIMARY KEY (coluna1, coluna2, ...);

-- Foreign Key
ALTER TABLE nome_tabela 
ADD CONSTRAINT nome_constraint 
FOREIGN KEY (coluna) REFERENCES outra_tabela(coluna);

-- Unique
ALTER TABLE nome_tabela 
ADD CONSTRAINT nome_constraint UNIQUE (coluna);

-- Check
ALTER TABLE nome_tabela 
ADD CONSTRAINT nome_constraint CHECK (condicao);

-- Exemplos
ALTER TABLE usuarios 
ADD CONSTRAINT pk_usuarios PRIMARY KEY (id);

ALTER TABLE pedidos 
ADD CONSTRAINT fk_pedidos_usuario 
FOREIGN KEY (usuario_id) REFERENCES usuarios(id);

ALTER TABLE produtos 
ADD CONSTRAINT uk_produtos_sku UNIQUE (sku);

ALTER TABLE funcionarios 
ADD CONSTRAINT ck_salario_positivo 
CHECK (salario > 0);

Remover Constraints da tabela

ALTER TABLE nome_tabela 
DROP CONSTRAINT nome_constraint [CASCADE | RESTRICT];

-- Exemplos
ALTER TABLE produtos 
DROP CONSTRAINT uk_produtos_sku;

ALTER TABLE pedidos 
DROP CONSTRAINT fk_pedidos_usuario CASCADE;

Renomear Constraints da tabela

ALTER TABLE nome_tabela 
RENAME CONSTRAINT nome_atual TO novo_nome;

-- Exemplo
ALTER TABLE usuarios 
RENAME CONSTRAINT usuarios_pkey TO pk_usuarios;

Modificando a Tabela

Renomear Tabela

ALTER TABLE nome_atual 
RENAME TO novo_nome;

-- Exemplos
ALTER TABLE usuarios 
RENAME TO users;

ALTER TABLE produto 
RENAME TO produtos;

Operações em Lote (Múltiplas Alterações)

Na maioria das vezes é mais eficiente fazer multiplas alterações. 

-- Múltiplas alterações em um comando (mais eficiente)
ALTER TABLE produtos 
    ADD COLUMN marca VARCHAR(50),
    ADD COLUMN categoria VARCHAR(30),
    ALTER COLUMN preco TYPE DECIMAL(12,2),
    ADD CONSTRAINT ck_preco_positivo CHECK (preco > 0),
    RENAME COLUMN descricao TO descricao_completa;

Comando DROP: Excluindo Estruturas

O comando DROP TABLE é usado para remover permanentemente uma tabela e todos os seus dados do banco de dados. **Use com extrema cautela**, pois a operação é destrutiva e irreversível.

Quando usar DROP TABLE?

  • Limpar estruturas obsoletas.
  • Excluir tabelas de staging após processamento.
  • Remover dados sensíveis permanentemente.
  • Gerenciar ciclo de vida do banco de dados.
DROP TABLE [IF EXISTS] nome_tabela [, ...] 
[CASCADE | RESTRICT];
🚫 AVISO: Isso apaga a tabela e todos os seus dados.

Componentes da Sintaxe:

  • IF EXISTS: Evita erro se a tabela não existir.
  • nome_tabela: Nome da tabela a ser removida.
  • CASCADE: Remove objetos dependentes automaticamente.
  • RESTRICT: Impede remoção se houver dependências (padrão).

EXERCÍCIOS DDL - SISTEMA DE NOTA FISCAL

Vamos praticar a definição de estruturas com um sistema completo de nota fiscal.

CREATE TABLE (10 Exercícios)

📘 Exercício CREATE 1: Tabela Básica de Nota Fiscal

A empresa XPTO precisa armazenar informações de notas fiscais. Crie a tabela nota_fiscal com os campos: numero (INTEGER), data_emissao (DATE), valor_total (DECIMAL), cliente_nome (VARCHAR(100)), cliente_cpf (VARCHAR(14)). Não adicione constraints ainda. 

CREATE TABLE nota_fiscal (
    numero INTEGER,
    data_emissao DATE,
    valor_total DECIMAL(10,2),
    cliente_nome VARCHAR(100),
    cliente_cpf VARCHAR(14)
);
📘 Exercício CREATE 2: Tabela de Itens da Nota

Agora crie a tabela itens_nota_fiscal para armazenar os produtos de cada nota: id_item (INTEGER), numero_nota (INTEGER), produto_codigo (VARCHAR(20)), produto_descricao (VARCHAR(200)), quantidade (DECIMAL), valor_unitario (DECIMAL). 

CREATE TABLE itens_nota_fiscal (
    id_item INTEGER,
    numero_nota INTEGER,
    produto_codigo VARCHAR(20),
    produto_descricao VARCHAR(200),
    quantidade DECIMAL(10,3),
    valor_unitario DECIMAL(10,2)
);
📘 Exercício CREATE 3: Tabela de Clientes

Crie a tabela clientes para normalizar os dados: cliente_id (SERIAL), nome (VARCHAR(100)), cpf (VARCHAR(14)), email (VARCHAR(100)), telefone (VARCHAR(15)). 

CREATE TABLE clientes (
    cliente_id SERIAL,
    nome VARCHAR(100),
    cpf VARCHAR(14),
    email VARCHAR(100),
    telefone VARCHAR(15)
);
📘 Exercício CREATE 4: Tabela de Produtos

Crie a tabela produtos com: produto_id (SERIAL), codigo (VARCHAR(20)), descricao (VARCHAR(200)), preco (DECIMAL), estoque (INTEGER). 

CREATE TABLE produtos (
    produto_id SERIAL,
    codigo VARCHAR(20),
    descricao VARCHAR(200),
    preco DECIMAL(10,2),
    estoque INTEGER
);
📘 Exercício CREATE 5: Tabela com Primary Key

Recrie a tabela nota_fiscal adicionando numero como PRIMARY KEY e cliente_id como FOREIGN KEY referenciando a tabela clientes. 

CREATE TABLE nota_fiscal (
    numero INTEGER PRIMARY KEY,
    data_emissao DATE,
    valor_total DECIMAL(10,2),
    cliente_id INTEGER,
    FOREIGN KEY (cliente_id) REFERENCES clientes(cliente_id)
);
📘 Exercício CREATE 6: Tabela com Constraints

Recrie a tabela itens_nota_fiscal com: PRIMARY KEY composta (numero_nota, id_item), FOREIGN KEY para nota_fiscal e produtos, e CHECK para quantidade > 0. 

CREATE TABLE itens_nota_fiscal (
    id_item INTEGER,
    numero_nota INTEGER,
    produto_id INTEGER,
    quantidade DECIMAL(10,3) CHECK (quantidade > 0),
    valor_unitario DECIMAL(10,2) CHECK (valor_unitario >= 0),
    PRIMARY KEY (numero_nota, id_item),
    FOREIGN KEY (numero_nota) REFERENCES nota_fiscal(numero),
    FOREIGN KEY (produto_id) REFERENCES produtos(produto_id)
);
📘 Exercício CREATE 7: Tabela com Valores Padrão

Crie a tabela configuracoes com: config_id (SERIAL PRIMARY KEY), empresa_nome (VARCHAR(100) DEFAULT 'XPTO Ltda'), data_criacao (TIMESTAMP DEFAULT CURRENT_TIMESTAMP), ativo (BOOLEAN DEFAULT TRUE). 

CREATE TABLE configuracoes (
    config_id SERIAL PRIMARY KEY,
    empresa_nome VARCHAR(100) DEFAULT 'XPTO Ltda',
    data_criacao TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    ativo BOOLEAN DEFAULT TRUE
);
📘 Exercício CREATE 8: Tabela com Unique Constraint

Modifique a criação da tabela clientes para incluir UNIQUE constraint no CPF e NOT NULL no nome. 

CREATE TABLE clientes (
    cliente_id SERIAL PRIMARY KEY,
    nome VARCHAR(100) NOT NULL,
    cpf VARCHAR(14) UNIQUE,
    email VARCHAR(100),
    telefone VARCHAR(15)
);
📘 Exercício CREATE 9: Tabela com Múltiplas Constraints

Crie a tabela produtos com: PRIMARY KEY, UNIQUE no código, CHECK para preço positivo, e DEFAULT 0 no estoque. 

CREATE TABLE produtos (
    produto_id SERIAL PRIMARY KEY,
    codigo VARCHAR(20) UNIQUE NOT NULL,
    descricao VARCHAR(200) NOT NULL,
    preco DECIMAL(10,2) CHECK (preco >= 0),
    estoque INTEGER DEFAULT 0 CHECK (estoque >= 0)
);
📘 Exercício CREATE 10: Tabela com Herança

Crie uma tabela pessoas com dados básicos e tabelas clientes e fornecedores que herdam de pessoas. 

CREATE TABLE pessoas (
    pessoa_id SERIAL PRIMARY KEY,
    nome VARCHAR(100) NOT NULL,
    cpf_cnpj VARCHAR(20),
    email VARCHAR(100)
);

CREATE TABLE clientes (
    tipo_cliente VARCHAR(20),
    data_cadastro DATE DEFAULT CURRENT_DATE
) INHERITS (pessoas);

CREATE TABLE fornecedores (
    ramo_atuacao VARCHAR(50),
    data_cadastro DATE DEFAULT CURRENT_DATE
) INHERITS (pessoas);

🗑️ Exercício DROP 8: Verificar Dependências Antes de Remover

Verifique as dependências da tabela produtos antes de tentar removê-la. 

-- Verificar dependências
SELECT 
    tc.table_name as tabela_dependente,
    kcu.column_name as coluna_fk
FROM information_schema.table_constraints tc
JOIN information_schema.key_column_usage kcu 
    ON tc.constraint_name = kcu.constraint_name
WHERE tc.constraint_type = 'FOREIGN KEY'
AND tc.table_name != 'produtos'
AND kcu.referenced_table_name = 'produtos';

-- Se houver dependências, usar CASCADE ou remover manualmente primeiro
