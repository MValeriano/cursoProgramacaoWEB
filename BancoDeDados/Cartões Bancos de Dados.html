Cartões Didáticos de Bancos de Dados

Conceitos Fundamentais, Design e Normalização

1. Conceito Fundamental de Banco de Dados Relacional

1

O que é um Banco de Dados Relacional (BDR)?

1

Um BDR é um tipo de banco de dados que representa os dados como coleções de tabelas, também chamadas de relações.

2

Qual é a base fundamental desse modelo?

2

O modelo relacional é fundamentado na teoria dos conjuntos e na lógica de predicados de primeira ordem.

2. Origem e Uso Comum

3

Quem introduziu o modelo relacional e quando?

3

Foi introduzido por Ted Codd da IBM Research em 1970.

4

Qual é o termo técnico que geralmente se usa para "banco de dados" em um contexto profissional?

4

Profissionalmente, o termo "banco de dados" geralmente se refere a um Sistema de Gerenciamento de Banco de Dados Relacional (RDBMS).

3. Funções Críticas da SQL

5

Qual é o papel dos comandos SQL em relação aos BDRs?

5

Os comandos SQL (como DDL e DML) formam a base para a interação com bancos de dados relacionais. Eles permitem a criação da estrutura (DDL) e a manipulação e recuperação de dados (DML e consultas) de forma eficiente.

4. A Importância do Design de Banco de Dados

6

Por que é crucial ter um design de banco de dados relacional robusto e planejado?

6

Um bom design inicial é a chave para um banco de dados resiliente e de fácil manutenção. Um design robusto de tabelas e relacionamentos bem planejados permite criar associações de forma fácil e eficiente.

7

Quais são as perguntas críticas que devem orientar o design?

7

As perguntas críticas incluem: Quais são os requisitos do negócio? Que tabelas serão necessárias? Que colunas cada tabela conterá? Como as tabelas serão normalizadas? Quais serão seus relacionamentos pai/filho?.

5. Integridade de Dados (Restrições de Chave Estrangeira)

8

Qual é a principal função das restrições de chave externa?

8

Elas são cruciais para a integridade dos dados. Elas impedem a inserção de registros "órfãos" (registros filhos sem um pai correspondente).

9

O que acontece se um usuário tentar inserir um registro "órfão"?

9

Uma tentativa de inserir um registro com um valor de chave externa que não existe na tabela pai resultará em um erro, demonstrando a funcionalidade da restrição.

6. Conceito de Normalização

10

Qual é o propósito do processo de normalização em um projeto relacional?

10

O processo de normalização visa alcançar propriedades desejáveis, sendo as principais: minimização de redundância e minimização de anomalias (inserção, exclusão e atualização).

11

Quais são os dois critérios formais que uma decomposição (divisão de tabelas) deve garantir para ser considerada um bom projeto?

11

1. Propriedade da junção sem perda (ou não aditiva), que é extremamente crítica e deve ser alcançada a qualquer preço. 2. Propriedade da preservação da dependência, que garante que cada dependência funcional será representada.

7. Mapeamento de Modelos

12

O que é o Mapeamento no contexto do design de banco de dados?

12

O Mapeamento (ou Projeto Lógico) é a fase em que o esquema conceitual de alto nível (geralmente criado usando modelos ER ou EER) é transformado em um esquema de banco de dados que segue um modelo de dados específico, como o relacional.

8. Diferença entre Álgebra e Cálculo Relacional

13

Qual a diferença fundamental entre a Álgebra Relacional e o Cálculo Relacional em termos de como a consulta é especificada?

13

A Álgebra Relacional é uma linguagem procedural (deve-se escrever uma sequência de operações, especificando *como* recuperar os dados). Já o Cálculo Relacional é uma linguagem não procedural (especifica *o que* será recuperado, sem descrever como fazê-lo).
