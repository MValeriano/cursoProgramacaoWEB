Aula: Mapeamento de Modelos de Dados

Do Modelo Conceitual ao Físico na prática

O Processo de Modelagem de Dados

A modelagem de dados é o processo de criar um plano visual ou um diagrama que define a estrutura de um banco de dados. Este processo é dividido em três fases:

  • 1. Modelo Conceitual: Representa as entidades e seus relacionamentos de forma de alto nível, sem se preocupar com a tecnologia.
  • 2. Modelo Lógico: Detalha a estrutura do banco de dados, incluindo tabelas, colunas, chaves primárias e estrangeiras. É agnóstico ao SGBD.
  • 3. Modelo Físico: Especifica a implementação no SGBD, definindo tipos de dados, índices e restrições específicas da plataforma (ex: PostgreSQL, MySQL).

Mapeando da Feirinha Virtual

1. Modelo Conceitual (Diagrama de Entidade-Relacionamento)

Nesta fase, identificamos as entidades do nosso sistema de "Feirinha Virtual" e como elas se relacionam.

  • **Usuários:** Podem ser clientes ou vendedores.
  • **Categorias:** Para classificar os produtos.
  • **Produtos:** Pertencem a uma categoria e são vendidos por um usuário (vendedor).
  • **Favoritos:** Uma lista de produtos que um usuário gosta.

Modelo Conceitual da Feirinha Virtual.

Cardinalidade dos Relacionamentos

As cardinalidades descrevem a quantidade de instâncias de uma entidade que se relacionam com instâncias de outra.

  • Usuários e Produtos (1:N): Um **usuário** (vendedor) pode ter **vários produtos**, mas um **produto** pertence a apenas um **usuário**.

    Relacionamento 1:N entre Usuário e Produto.

  • Categorias e Produtos (1:N): Uma **categoria** pode ter **vários produtos**, mas um **produto** pertence a apenas uma **categoria**.

    Relacionamento 1:N entre Categoria e Produto.

  • Usuários e Favoritos (N:M): Um **usuário** pode ter **vários produtos favoritos**, e um **produto** pode ser favorito de **vários usuários**.

    Relacionamento N:M entre Usuário e Favoritos.

Mapeamento para o Modelo Lógico

Aqui, convertemos as entidades e relacionamentos em tabelas e colunas, adicionando as chaves primárias e estrangeiras.

Regras de Conversão
  • **Entidades** se tornam **tabelas**.
  • **Atributos** se tornam **colunas**.
  • **Relacionamentos 1:N:** A chave primária da tabela "1" se torna uma chave estrangeira na tabela "N".
  • **Relacionamentos N:M:** É criada uma **tabela intermediária** que armazena as chaves primárias das duas tabelas.

Mapeamento para o Modelo Físico

Nesta etapa final, o modelo lógico é adaptado para um SGBD específico, adicionando detalhes como tipos de dados exatos e restrições. No nosso caso, usaremos a sintaxe do PostgreSQL.

Exemplo Físico (PostgreSQL)
-- Criação da tabela de Usuários
CREATE TABLE usuarios (
    usuario_id SERIAL PRIMARY KEY,
    nome VARCHAR(255) NOT NULL,
    email VARCHAR(255) UNIQUE NOT NULL
);

-- Criação da tabela de Categorias
CREATE TABLE categorias (
    categoria_id SERIAL PRIMARY KEY,
    nome VARCHAR(100) NOT NULL
);

-- Criação da tabela de Produtos
CREATE TABLE produtos (
    produto_id SERIAL PRIMARY KEY,
    nome VARCHAR(255) NOT NULL,
    descricao TEXT,
    preco DECIMAL(10, 2) NOT NULL,
    estoque INTEGER DEFAULT 0,
    usuario_id INTEGER REFERENCES usuarios(usuario_id),
    categoria_id INTEGER REFERENCES categorias(categoria_id)
);

-- Criação da tabela de Favoritos (Tabela N:M)
CREATE TABLE favoritos (
    usuario_id INTEGER REFERENCES usuarios(usuario_id),
    produto_id INTEGER REFERENCES produtos(produto_id),
    data_favoritado TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (usuario_id, produto_id)
);
